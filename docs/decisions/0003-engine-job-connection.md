# 0003. 실제 정제·계산 작업 연결

상태: 구현·실제 개발 환경 정제/계산 흐름 확인(2026-11-04). GitHub #73 / Jira IPGO-111, 배포 IPGO-118.

현재 역할·저장 방식과 보류 범위는 [AWS 데이터 접근 계약](0001-aws-data-access-contract.md)을
함께 확인합니다. 개발 화면 시험의 성공과 실제 LLM·직접 입력 시나리오·백테스트 서버 연결·
장시간 운영 검증을 구분합니다.

업로드와 설정·발주 변경의 트랜잭션에 `engine_jobs`를 함께 저장한다. 트랜잭션 밖에서
SQS로 전송하며 전송과 상태 기록 사이 종료에는 같은 jobId를 재사용한다. 60초 lease와
전송 후 20분 재전송 간격을 쓰며 두 시간 미완료 작업은 고정 오류의 실패 상태로 종료한다.
확정된 최종 상태에 늦게 온 결과는 다시 저장하지 않는다. 원본/계산 입력과 이전 성공 결과는 유지한다.

결과 수신은 warehouse → job → upload/run 순서로 잠그고 식별자·소유권·입력 snapshot·상품 집합과
숫자·시나리오를 검증한다. 정제 저장과 후속 계산 작업 생성, 계산 결과·시나리오·DONE 상태는
각각 하나의 트랜잭션이다. 결과 큐 ACK는 해당 트랜잭션의 commit 이후에만 수행한다.
DB 실패 또는 잘못된 결과는 ACK하지 않아 재시도/DLQ로 가며, 원문과 인증정보는 로그에 남기지 않는다.

CLEAN은 파일 하나이며 uploadId=uploadFileId, jobId는 별도 UUID다. Spring이 지정한
previousUploadFileId는 같은 창고 직전 달의 최신 revision이 DONE일 때만 존재한다.
AI는 V14의 세 조회 전용 view에서 회원·창고·원본과 최신 revision을 검증하고 월말 재고를 읽는다.
월말 기록이 없는 전월 자료는 빈 재고로 대체하지 않는다. source·상품 기본 표에 AI 권한을 주지 않는다.

계산은 확정된 기본 설정 이후 최신 revision의 DONE 자료로 시작한다. 비활성 상품과 날짜 없는 발주는
빼고, 자료에서 검산 제외된 상품은 EXCLUDED로 보존한다. 설정·원가가 없으면 NOT_CALCULABLE이다.
백테스트 선정 전 정책은 계약의 B/1.00이며 가장 최근 실행의 입력 hash가 같고 QUEUED/RUNNING/DONE일 때만 재사용한다.
조건이 이전 값으로 돌아오거나 최근 실행이 실패하면 새 실행을 만들고 과거 성공으로 되돌리지 않는다.
객체 키 순서와 숫자의 decimal scale을 정규화해 프로세스 재시작/DB 재조회에도 같은 hash를 만든다.
S2 recalculate=true는 새 실행을 만들고 재활성화·원가 수정은 입력이 달라지면 계산을 시작한다.
발주 자동 입고 매칭과 판매 중단 기간 정책은 이번에 추측하지 않는다.

AI API와 worker는 단일 프로세스/한 개 작업 슬롯을 공유하며 독립 worker 서비스는 0개다.
실제 계산과 유료 LLM은 별도이며 LLM 미활성 상태의 정상 계산 인사이트는 NONE/DISABLED로 저장해
K4가 TABLE_ONLY를 반환한다. 미구현 위험·정확도 값은 null을 유지한다.

V14는 outbox·조회 view·입력 hash를 추가하고 계산 사유의 문자열 길이만 늘린다.
기존 데이터/PROCESSING 행을 일괄 변경하거나 재전송하지 않는다. 원복 시 새 발송/worker를 끄고
기존 mock task revision을 사용하며 schema를 지우지 않는다. 실제 적용 전 snapshot, 기존 이미지의
새 schema 호환과 재시작 영향을 검증한다.
