# 1921~1925 전환과 기존 배치 합산 5회 예산

관련 #118, 이전 #115/#116. 기존 배포의 812~816은 현재 화면에서 과거 결과가 되어 유료 시도0으로
차단됐다. 사용자는 상품33~37의 결과1921~1925로 전환하는 **준비·검증만** 요청했다.
811/698·상시 자동 설명은 제외하고 배포/유료는 별도 승인한다.

## 범위와 전체 예산

batch ID `master-current-20261105`, 소유자1, 총 최대5회는 유지한다. 생성 허용 ID만1921~1925로
고정한다. 기존812~816과 새1921~1925를 합쳐 최대5회이며, 새 배포를 새로운5회 승인으로 해석하지 않는다.
기존811 단건 예산은 이 배치에 합산하거나 재사용하지 않는다.

812~816의 기존 다섯 설명행을 전체 예산 풀로 계속 사용한다. 기존 버전에서 이미 쓴 행은 그대로
소비한 슬롯이다. 남은 슬롯은 새 다섯 결과 중 어느 대상에나 사용할 수 있다. 예를 들어 기존2회 성공이면
새5건 중 원하는3건까지만 가능하다. 같은 상품의 기존 결과가 쓰였다는 이유만으로 새 결과를 막지는 않는다.
한 새 결과를 다시 호출하는 것은 거부한다. 요청/환경변수는 대상·예산·슬롯을 선택하거나 늘릴 수 없다.

기존5행과 새5행을 ID 순서로 잠그고 소유자/상품 결합·현재 화면·입력·미사용을 확인한다.
첫 미사용 예산행과 새 결과의 PROCESSING/입력/표식을 같은 REQUIRES_NEW transaction에서 commit한 뒤에만
새 결과 HTTP를 한 번 호출한다. 예산행이나 결과행을 새로 만들지 않고, 하나라도 없거나 표식이 모순이면 차단한다.
commit 후 프로세스가 죽거나 저장/통신/응답이 불명확해도 한도는 환불하지 않는다.

## 배포된 구버전도 차단하는 표식

선택한 기존 예산행에는 구버전이 이미 아는 원래 `batch/{batchId}/{oldId}/attempt-1` 표식을 쓴다.
status는 **SKIPPED**, validation_passed=false로 두고 versions에
`batchBudgetDelegate={batchId,anchorResultId,resultId}`를 추가한다. 원래 versions 키는 보존한다.
mode=NONE, reason_code=LLM_DISABLED, 원문/문장/수량/비용/token/created_at은 보존하므로
기존 공개 GET의 TABLE_ONLY/isFallback=false/생성시각은 변하지 않는다. LLM 성공이나 실패를 꾸미지 않는다.

배포된6fbb792 버전은 자기 표식+SKIPPED를 보면 전체 배치를 중단한다. 따라서 구버전 gate의 STOPPED_AFTER_FAILURE 문구는 이 경우 예산 위임으로 인한 차단이며 실제 LLM 실패를 뜻하지 않는다. 새 시도1회 예약 후에는
구버전 복귀/동시 인스턴스가 다른 미사용 기존 결과로 추가 호출할 수 없다. 구버전 recovery는 PROCESSING만
처리하므로 예산행에 새 문장의 fallback을 잘못 저장하지 않는다.

새 버전은 delegate가 가리킨 새 결과의 실제 처리 상태를 읽는다. 이전 시도가 검사를 통과한 LLM/DONE이면
남은 새 대상을 처리할 수 있고, 진행 중이면 직렬화하며 실패/불명확/metadata 불일치면 나머지도 차단한다.
중복 delegate·단독 새 표식·알 수 없는 기존 표식·이미 발생한 미연결 비용은 새 예산으로 해석하지 않는다.
기존 버전의 실제 PROCESSING과 새 버전의 PROCESSING 모두 timeout+30초 후 기본문장으로만 마감하며
복구 과정에서 공급자를 호출하지 않는다.

## API·배포·복구

GET/POST 경로와 batch ID는 유지한다. GET targets는1921~1925이고 `reservedByAnchorResultId`는 실제
예약에 사용한 기존 행 ID(미예약이면null)다. reservedAttempts는 기존 실제 시도+새 위임 예약의 합계다.
remainingAttempts는 전체 잔여 예산과 현재 READY 대상 수 중 작은 값이며, gate가 닫혔으면0이다.
새 POST에서812~816/811/698/다른ID는403, 본문은400이다. GET은 읽기 전용이다.

batch_enabled/approved 기본false, 자동/worker/811단건과 동시 활성화 거부는 유지한다.
별도 schema/migration·모델/프롬프트·키 변경은 없다. 실제 배포 전 최신 소스와 S3/Flyway OFF 등
운영 상태를 재확인한다. 승인 후 정상 마스터로 현재 결과/입력/공유 예산을 확인하고 READY만 순차 처리한다.
실패·응답 불명확이면 재시도와 나머지 호출을 중단한다. 로컬 배타적 시도 원장도 호출 전에 기록한다.

롤백 전 새 PROCESSING을 새 recovery로 기본문장 마감한다. 구버전만으로는 새 ID의 recovery를 하지 못해
GET202가 남을 수 있다. 기존 예산행의 SKIPPED/표식/versions와 새 시도는 삭제·초기화하지 않는다.
구버전에서 추가 호출이 차단되는 것은 정상이다. 배포 자체를 되돌려도 새로운 승인 예산은 생기지 않는다.

## 검증 출처

합성 DB/로컬 HTTP/실제 FastAPI 검사기+FakeClient로 검증하며 공급자 키·유료 호출은 사용하지 않는다.
구버전 구현은 실제6fbb792 소스를 테스트 전용으로 고정한 LegacyInsightBatch/Manifest다.
이름과 Spring component 등록만 변경했다. 교차 버전 테스트의 구버전 current-view는 과거 실제 DTO를
고정한 mock으로 통과시켜, 과거 결과 검사에 가려지지 않고 예산 자체가 막는 것을 확인한다.
이 합성 mock은 실제 업무 실행·실제 UI 성공이 아니다. 실제 운영 읽기와 최종 검사 결과는 PR/운영 기록에 분리한다.
