# 구독 해지 사유 저장 (#159)

`POST /api/billing/subscription/cancel`은 기존처럼 Bearer 인증과 `Idempotency-Key`를 받고 유료기간을 보존한 채 다음 청구를 중단한다. 선택 사유는 해지와 같은 트랜잭션에 저장한다. 해지 사유를 고르지 않아도 해지할 수 있다. ONE_TIME 모드의 정기결제 차단 정책은 그대로다.

```json
{"reasons":["PRICE","OTHER_SERVICE"],"note":"선택 메모"}
```

| 코드 | 현재 화면 문구 |
|---|---|
| PRICE | 가격이 부담돼요 |
| NOT_USING | 생각보다 잘 안 써요 |
| PREDICTION_QUALITY | 예측이 잘 안 맞아요 |
| OTHER_SERVICE | 다른 서비스를 쓸래요 |
| OTHER | 기타 |
| MISSING_FEATURE | 초기 단일 reason 계약 호환용 |

본문 생략·`{}`·빈 reasons는 허용한다. 초기 제안인 `{reason:"PRICE",note?:string}`도 받으며 비어 있지 않은 reasons와 reason을 동시에 보내면400이다. reasons는 최대6개 입력을 받고 null/알 수 없는 코드는400, 중복 제거 후 코드순으로 저장한다. note는 선택500자 이내이며 앞뒤 공백을 제거하고 빈 값은 없는 것으로 본다. NUL은400이다. 요청 객체 문자열 출력은 메모를 가린다. 메모에는 결제·인증정보를 넣지 않는다.

V33은 `billing_commands`에 nullable `cancellation_reason_codes`(콤마로 구분한 정렬된 코드)와 `cancellation_note`를 추가한다. 과거 명령은 NULL로 두고 사유를 추정하지 않는다. 서버의 기존 테이블 권한을 사용하며 AI 역할의 읽기 금지는 유지한다. note는 회원 탈퇴 트랜잭션에서 제거하고 사유 코드·명령·결제 이력은 보존한다.

같은 사용자·명령 키·정규화된 같은 사유/메모는 원래 명령을 재사용한다. 순서/중복/앞뒤 공백만 바뀐 요청도 같다. 다른 본문으로 같은 키를 보내면409 `IDEMPOTENCY_KEY_REUSED`이며 사유와 구독을 덮어쓰지 않는다. 본문 없는 기존 명령과 빈 사유/메모는 기존 빈 본문 hash와 호환된다. 원장 저장 실패 시 해지도 rollback된다. 해지와 재개는 새 승인·환불을 만들지 않는다.

Client는 복수 선택을 reasons 코드 배열로 보내고 브라우저 사유 저장을 새로 쓰거나 읽지 않는다. 과거 localStorage 값의 자동 이전/삭제는 하지 않는다. 실패 뒤 같은 본문 재시도는 같은 키, 사유가 달라지면 새 키를 사용한다.

적용 순서는 V33과 서버 계약 → Client 전송 변경이다. Server 이전에 Client만 바꾸면 이전 서버는 본문을 저장하지 않으므로 완료로 보지 않는다. 개발/운영 DB 적용·배포·실제 계정 검증은 별도 승인 범위다. 기존 앱은 새 컬럼을 무시할 수 있으므로 복구 시 컬럼과 저장 이력을 삭제하지 말고 직전 앱으로 되돌린 뒤 상태를 확인한다. 프론트만 구버전으로 되돌리면 사유 없는 해지로 동작한다.
