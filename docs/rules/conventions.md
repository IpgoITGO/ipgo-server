# 작성 규칙

## 공통 원칙

- Issue와 PR은 한국어로 작성합니다.
- API, database, middleware처럼 익숙한 기술 용어는 그대로 사용합니다.
- 비전공자가 목적과 영향을 이해할 수 있는 표현을 우선합니다.
- 한 문단은 2~3문장, 한 bullet은 한 가지 내용으로 제한합니다.

## Issue

```markdown
## 목적
> 해결할 내용을 한 줄로 작성

## 작업
- [ ] 작업 항목

## 완료 조건
- [ ] 확인 가능한 결과

## 제외 범위
- 다루지 않는 내용
```

## commit

`type: short English summary` 형식을 사용합니다. 기본 type은 `feat`, `fix`, `docs`, `refactor`, `test`, `chore`, `perf`, `ci`입니다.

## PR과 Markdown

- 변경은 표, 할 일과 검증은 체크리스트로 표현합니다.
- 순서나 관계가 복잡할 때만 Mermaid를 사용합니다.
- 긴 로그는 `<details>`로 접고 핵심 결과를 먼저 씁니다.
- 충돌 위험도는 `낮음`, `보통`, `높음`으로 표시하고 충돌 영역과 예방 방법을 함께 씁니다.
- 본문은 기본적으로 30줄 안팎으로 유지하고 긴 설계는 `docs/`에 기록합니다.
