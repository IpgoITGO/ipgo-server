## 최종 검증

- H2 관련132건: 실패/오류/생략0. 기존 인증·접근 제어·업로드·상품·설정·계산·예정 입고 회귀를 포함한다.
- 폐기용 PostgreSQL16: 서버 역할로 빌링53건, 실패/오류/생략0. 전체 migration SQL,30테이블, FK/중복 방지 index, AI 역할 읽기 차단을 확인했다.
- H2는 transaction 완료까지 유지하는 JVM lock, PostgreSQL은 실제 DB advisory lock 경로를 각각 실행했다. H2 결과를 다중 배포 안정성의 증거로 확대하지 않는다.
- Java21 bootJar·diff·검증 script 구문 통과. README의 기존 빌링 계약 링크는 여전히 유효해 README 내용은 바꾸지 않았다.

키 발급/청구/조회는 가짜 BillingGateway 또는 mock HttpClient로 검사했다. 실제 토스 상점·브라우저·네트워크 결제·웹훅 전달·배포·장기 안정성 검증이 아니다. H2와 PostgreSQL의 겹치는 검사를 실사용 표본으로 합산하지 않는다.

## 적용과 복구 경계

원격에 공유·배포하지 않은 V17을 보완했으며 운영 DB를 변경하지 않았다. 이미 V17을 적용한 환경이 있다면 checksum 우회/수정 migration 재실행 대신 별도 이관을 준비해야 한다. 검증용 컨테이너/network는 제거했다.

API와 작업기는 기본 OFF, TEST 전용을 유지한다. 실제 테스트 결제나 배포는 구현 확인 뒤 별도 지시가 필요하다. 키 rotation, AI 월 횟수 집계, 환불/일할 계산, 조직/좌석,24시간 운영 등 기존 후속 범위는 유지한다.

향후 문제 발생 시 신규 등록/청구를 먼저 중단하고 진행/미확정 주문을 조회·대조한다. 원장과 이미 승인된 결제를 삭제하거나 자동 환불하지 않는다. 이번 검토 범위의 필수 잔여 작업과 사용자 즉시 조작은 없다.
